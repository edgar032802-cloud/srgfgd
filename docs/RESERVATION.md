# 체험 예약 — 운영 안내

부스 앞에 줄을 세우지 않고, 방문자가 자기 휴대폰으로 예약하고 순서를 확인하게 하는 기능이다.
활동 넷(감각등록·감각추구·감각예민·감각회피)이 **각자 따로 줄을 선다.**

## 1. 지금 되는 것 / 아직 안 되는 것

| | 상태 |
|---|---|
| 이름·전화번호·학과로 예약 | **된다** |
| 현재 대기 팀 수 보기 | **된다** (15초마다 저절로 갱신) |
| 내 앞에 몇 팀 남았는지 보기 | **된다** |
| 운영자 화면에서 명단 보기 · 체험 완료 · 취소 | **된다** |
| **하루 정원 100팀** · 마감 · 자정 초기화 | **된다** (2026-09-16) — 3-1절 |
| 예약 접수 / 5팀 남았을 때 **문자 발송** | **된다** (2026-09-08 Solapi 연결) — 남은 것은 충전뿐, 4절 |

발송이 끊겨 있어도 예약은 정상으로 접수되고, 방문자 화면에는 자기 순서가 실시간으로 보인다.
운영 화면 맨 위 줄에 지금 발송이 붙어 있는지가 표시된다.

> **행사 전에 충전할 것.** 2026-09-08 기준 잔액 0원 / 포인트 300p 다. 문자 한 통 20원대,
> 한 팀에 두 통(접수·호출)이 나가므로 **팀당 약 40원** — 300p 로는 일고여덟 팀이면 동난다.
> 100팀을 받을 생각이면 5,000원쯤 충전해 두면 넉넉하다. (호출은 앞이 5팀 이하가 될 때만 나가므로,
> 줄이 길면 한동안 접수 한 통씩만 나간다.)

## 2. 행사 당일

```bash
npm run dev
```

방문자 휴대폰이 붙어야 하므로 **같은 와이파이**에서 노트북의 주소를 열어야 한다.

```bash
API_HOST=0.0.0.0 npm run dev -- --host
```

- 터미널에 뜨는 `Network: http://192.168.x.x:5173` 이 방문자가 열 주소다. QR 코드로 만들어 부스에 붙이면 된다.
- `API_HOST=0.0.0.0` 은 같은 와이파이의 아무나 접속할 수 있게 여는 설정이다. **행사 중에만 쓰고 끝나면 되돌릴 것.**
- 예약 기록은 `server/data/booth.json` 파일 하나에 쌓인다. 노트북을 껐다 켜도 남아 있다.

## 3. 운영 화면

1. 화면 맨 아래 **푸터의 프리지아 로고를 2.5초 안에 다섯 번** 누른다.
2. 비밀번호 **3618** 을 넣는다.
3. 활동별 대기 팀 수와 예약자 명단이 뜬다.

- **이름으로 찾기** — 맨 위 검색칸에 이름(또는 번호 뒷자리)을 넣으면 그 사람이 잡아 둔 예약이 **날짜와 함께** 활동별로 한 번에 뜬다(지난날 기록까지). 한 사람이 네 활동에 다 줄을 설 수 있어서, "제가 예약했는데요" 하고 오는 사람을 가릴 때 쓴다. 상태는 `진행 중`(그 줄 맨 앞), `호출함 · 앞 N팀`, `대기 · 앞 N팀`, `완료`/`취소`, `만료`(어제 대기로 남은 것) 중 하나다. 동명이인은 번호로 구분한다.
- **호출 상태가 줄마다 보인다** — `호출함`(실제로 나감), `호출할 차례(문자 미연결)`, **`호출 문자 실패 — 직접 불러 주세요`**. 실패가 뜨면 그 팀은 직접 부르면 된다.
- **체험 완료** — 그 팀을 줄에서 뺀다. 뒤에 선 팀이 한 칸씩 당겨지고, 그 순간 앞이 5팀 이하가 된 사람에게 "부스로 오세요" 안내가 나간다.
- **취소** — 안 온 팀을 뺀다. 완료와 똑같이 줄이 당겨진다. 노쇼 하나가 줄을 막지 않도록 반드시 쓸 것.
- 비밀번호는 **서버가 확인한다.** 화면 코드에는 정답이 없어서 개발자 도구로 뜯어봐도 명단이 나오지 않는다.
- 탭을 닫으면 로그인이 풀린다(sessionStorage). 부스 휴대폰을 잠깐 두고 가도 다음 사람이 명단을 열지 못한다.
- 비밀번호를 바꾸려면 `.env` 에 `BOOTH_ADMIN_PASSWORD=원하는번호`.

## 3-1. 하루 정원 · 마감 · 자정 초기화 (2026-09-16)

**체험존마다 하루 100팀.** 네 체험존이 각자 따로 센다.

| 상황 | 방문자 화면 | 서버 |
|---|---|---|
| 100팀 미만 | 예약 폼 | 접수 |
| 오늘 100팀이 찼다 | **오늘은 마감되었어요. 내일 다시 만나요.** | 101번째는 거절 |
| 운영자가 마감을 눌렀다 | 위와 같은 문구 | 거절 |
| 한국 시각 00시가 지났다 | 예약 폼 | 대기번호 1번부터 다시 |

- **정원은 "대기 + 완료"로 센다.** 취소한 팀(노쇼)의 자리는 다른 팀에게 돌아간다. 그래서 취소가 있었던 날은
  **대기번호가 100을 넘을 수 있다**(101, 102…). 고장이 아니다 — 번호는 한 번 쓰면 다시 쓰지 않는다.
- **이미 줄에 선 사람은** 정원이 차도 자기 순서를 계속 본다. 마감 안내는 새로 들어온 사람에게만 뜬다.
- 폼을 채우는 사이에 마감되면, 예약하기를 눌렀을 때 오류 대신 같은 마감 안내로 바뀐다.

### 마감 버튼

운영 화면의 체험존마다 머리에 마감 줄이 있다.

- **체험 완료가 100팀이 되어야 누를 수 있다.** 그 전에는 버튼이 막혀 있고 "N팀 더 완료하면 마감할 수 있어요"라고 뜬다.
  화면만 막는 게 아니라 서버도 한 번 더 확인한다(99팀에서 요청을 보내도 거절된다).
- 누르면 한 번 더 묻는다. 확인하면 그 체험존만 마감되고 다른 체험존은 그대로다.
- **잘못 눌렀으면 "마감 해제"** 로 되돌린다. 다만 완료가 이미 100팀이면 정원이 찬 상태라 해제해도 새 예약은 받지 않는다.
- 마감은 서버를 껐다 켜도 유지되고, 00시가 지나면 저절로 풀린다.

### 자정 초기화

**00시에 무엇을 "지우는" 작업은 없다.** 모든 조회가 "오늘" 기록만 보도록 되어 있어서 날짜가 바뀌면 저절로 새 줄이 된다.

- 한국 시각 기준이다. **서버가 UTC 로 돌아도**(Railway 가 그렇다) 한국 00시에 바뀐다. 서버 날짜를 그대로 썼다면
  한국 오전 9시에 줄이 통째로 초기화됐을 것이다.
- 타이머에 기대지 않으므로 **00시에 서버가 꺼져 있었어도** 켜지는 순간 새 날로 맞게 돈다.
- 어제 대기로 남아 있던 예약은 **만료**가 된다. 오늘 줄에 섞이지 않고, 그 사람 화면에서도 순서가 사라져 폼으로 돌아간다
  ("지금 입장해주세요"가 잘못 뜨지 않는다). 운영 화면에서 완료·취소할 수도 없다.
- **지난날 기록은 지워지지 않는다.** 줄과 버튼은 오늘 것만 보이지만, 이름 검색은 지난날까지 찾고 날짜를 함께 보여 준다.

### 검증한 것

**다시 돌리려면 `npm run test:booth`** (약 3분). 진짜 문자는 한 통도 나가지 않는다 — 키를 비우거나,
지연·실패를 흉내 내는 가짜 Solapi 서버(`SOLAPI_BASE_URL`)로 돌린다. 예약 파일도 임시 폴더를 쓴다.

실제 서버를 여러 대 띄워 규칙 85가지(`tests/booth-rules.test.mjs`)와 문자 경로 37가지(`tests/booth-sms.test.mjs`)를 확인했다(정원은 줄이지 않고 **실제 100**, 자정은 서버 시계를 23:59:40 으로
밀어 두고 **실제로 넘어가게** 해서).

- 1~100번째 예약 성공, 번호 1..100 빠짐없음, 101번째 거절, 다른 체험존 영향 없음
- 취소 → 자리 반환 → 새 번호 101(50 재사용 안 함) → 다시 가득
- 완료 0·99 에서 마감 거절, 100 에서 허용, 두 번 눌러도 이상 없음, 마감 후 예약 거절·문구 정확, 해제
- 자정 통과: 날짜 +1, 마감 풀림, 대기 0, 번호 1부터, 어제 대기는 만료·완료 불가, 어제 기록 보존
- 서버 시간대를 UTC·로스앤젤레스로 바꿔도 한국 날짜, 연말·윤년 경계
- 재시작 후 마감·완료 수·번호 유지, 깨진 예약 파일은 덮어쓰지 않고 옆에 백업
- 같은 IP 에서 50건 동시 예약 성공·번호 중복 없음

## 4. 발송 — 지금 상태와 문구

**2026-09-08 에 Solapi 계정을 붙였다. 지금은 문자(SMS)로 나간다.**

- 발신번호 등록 완료(ACTIVE, 2028-09-08 까지). 번호와 키는 `.env` 의 `SMS_SENDER`·`SOLAPI_*` 에 있고 git 에 올라가지 않는다 — 저장소가 공개돼도 개인 번호가 새지 않게 문서에도 적지 않는다.
- 키가 채팅으로 오간 값이라, 행사가 끝나면 Solapi 콘솔에서 **키를 새로 발급(폐기)** 해 두는 편이 안전하다.
- 확인은 운영 화면 위쪽 **테스트 발송** 으로. 자기 번호에 한 통 보내 보고 들어갈 것.
- **발송이 실패하면 운영 화면 맨 위에 이유가 그대로 뜬다**(2026-09-09). `HTTP 401 · 생성한 signature를 확인하세요` 면 키가 틀렸거나 앞뒤에 공백이 붙은 것이다. 같은 줄에 키·시크릿의 **글자 수**도 나온다 — Solapi 키는 16자, 시크릿은 32자다. 숫자가 다르면 붙여넣기가 잘못된 것이다.
- 환경변수 값은 서버가 스스로 다듬는다 — 앞뒤 공백, 따옴표, 값 안의 줄바꿈, 그리고 `SOLAPI_API_SECRET=값` 처럼 변수명까지 통째로 붙여 넣은 경우(마지막 `=` 뒤만 취한다)를 모두 잡는다. 대시보드 입력칸은 넣은 그대로 오기 때문에 이런 사고가 잦다.
- **지문으로 대조한다.** 화면에 키·시크릿의 글자 수와 함께 앞 여섯 자리 해시가 뜬다. 값 자체는 나오지 않으므로 안전하고, 올바른 값인지 눈으로 확인할 수 있다. 길이만 보면 "32자인데 다른 값"을 놓친다.
  - 키는 **16자**, 시크릿은 **32자**여야 한다. 숫자가 다르면 붙여넣기가 잘못된 것이다.

### 나가는 문구

**접수와 호출은 언제나 따로 간다.** 한 통으로 붙이면 "접수됐습니다"인지 "지금 오세요"인지 읽는 사람이 구분하지 못한다.
줄이 비어 있을 때 예약하면 접수 한 통이 가고 곧바로 호출 한 통이 따로 간다. 한 사람이 받는 문자는 언제나 두 통이다.

```
접수         [작업치료학과 프리지아] 홍길동님, 12번으로 접수되었습니다. 5팀 남으면 연락드립니다.   83바이트 · SMS
호출         홍길동님, 5팀 남았습니다. 부스 앞에서 대기해주세요.                            55바이트 · SMS
호출(차례)    홍길동님, 지금 입장해주세요. 부스 앞으로 와주세요.                             54바이트 · SMS
```

### 90바이트를 넘기지 말 것 — 요금 문제가 아니다

넘는 순간 SMS 가 LMS 가 되는데, LMS 에는 **제목(subject)** 이 붙는다. 휴대폰은 그 제목을 본문 위,
`[Web발신]` 보다 **앞줄에 굵게** 띄운다. 그리고 LMS 와 SMS 는 통신사에서 다른 경로로 나가
**짧은 SMS 가 긴 LMS 를 추월한다** — 접수(LMS)와 호출(SMS)을 함께 보냈더니 "지금 입장해주세요"가
먼저 도착한 사고가 실제로 있었다. 둘 다 SMS 면 경로가 같아 순서가 지켜지고, 제목 줄도 없고,
값도 통당 20원대다(**팀당 약 40원**).

세는 법은 한글 2, 영문·숫자 1. 이름이 유난히 길어 넘칠 것 같으면 `bookedText` 가 `작업치료학과` 를
스스로 떼어 90 안에 맞춘다.

### 그 밖에

- `[Web발신]` 자체는 **뗄 수 없다.** 웹·API 로 나가는 문자에 통신사가 붙이는 표시다.
  없애려면 알림톡이나 기업메시징(등록된 사업자용) 서비스로 가야 한다.
- `5팀 남으면` 의 숫자는 `CALL_AHEAD` 를 그대로 끼워 넣는다. 기준을 바꾸면 문구도 같이 바뀐다.
- **접수 문자와 호출 문자는 `CALL_DELAY_MS`(6초) 를 두고 나간다.** 줄이 짧을 때 예약하면 두 통이
  연달아 나가는데, 같은 초에 통신사로 들어가면 도착 순서가 보장되지 않는다. 예약 응답은 지연 없이
  먼저 돌아가므로 화면에서 자기 순서는 곧바로 보인다.
- **호출 문자에는 활동 이름이 들어가지 않는다**(사용자가 정한 문구). 한 사람이 여러 활동에 줄을 서 있으면
  어느 부스인지 문자만으로는 알 수 없다 — 넣으려면 `callUpText` 에 `ACTIVITIES[r.activity].title` 을 붙이면 된다.

### 카카오톡(알림톡)으로 바꾸고 싶다면

**웹페이지가 혼자서 카카오톡을 보낼 방법은 없다.** 모르는 번호로 카카오톡을 보내는 것은 *알림톡*이고,
알림톡을 쓰려면 다음이 전부 있어야 한다.

1. **카카오톡 채널** 개설 + 비즈니스 채널 전환
2. **발송 대행사** 계정 — Solapi(구 쿨SMS)·알리고·NHN Cloud 등. 이 코드는 **Solapi** 기준으로 붙여 두었다.
3. **템플릿 사전 심사** — 문구를 미리 등록해 승인받아야 한다(영업일 1~3일). 승인된 문구만 나간다.
4. **발신번호 사전 등록** — 학생회 대표번호 등

알림톡이 부담스러우면 **문자(SMS/LMS)만 써도 된다.** 채널도 템플릿 심사도 필요 없고,
대행사 계정과 발신번호 등록만 있으면 된다. 아래에서 `KAKAO_*` 를 비워 두면 자동으로 문자로 나간다.

`.env` 에 아래 셋은 이미 들어가 있다. 알림톡을 쓰려면 `KAKAO_*` 를 더 넣으면 되고,
비워 두면 지금처럼 문자로 나간다.

```
SOLAPI_API_KEY=...              # 넣어 둠
SOLAPI_API_SECRET=...           # 넣어 둠
SMS_SENDER=...                  # 넣어 둠 (등록 완료)

# 알림톡까지 쓸 때만
KAKAO_PFID=...                  # 카카오 채널 발신 프로필 id
KAKAO_TEMPLATE_BOOKED=...       # 접수 안내 템플릿 id
KAKAO_TEMPLATE_CALLUP=...       # 호출 템플릿 id
```

템플릿을 등록할 때 쓸 문구(치환 변수는 `#{name}` `#{title}` `#{teamNo}` `#{ahead}`):

- 접수 — `[프리지아] #{name}님 #{teamNo}번 접수. 앞에 #{ahead}팀. 순서 되면 다시 알려드릴게요.`
- 호출 — `[프리지아] #{name}님 앞에 #{ahead}팀! #{title} 부스로 와주세요.`

알림톡은 통당 8~10원대라 문자보다 싸지만, 채널·심사가 붙는다. 하루짜리 부스면 문자로 충분하다.

**발송에 실패해도 예약은 절대 실패하지 않는다** — 줄에 선 사람이 사라지면 안 되기 때문이다.
실패 기록은 각 예약에 남고, 운영 화면에서 순서를 보고 직접 부를 수 있다.

## 5. 개인정보

이름·전화번호·학과가 `server/data/booth.json` 에 평문으로 쌓인다.

- **행사가 끝나면 이 파일을 지울 것.** 지우면 그날의 명단이 전부 사라진다.
- 서버를 학교 밖 인터넷에 열어 두지 말 것. 같은 와이파이 안에서만 쓰는 것을 전제로 만들었다(HTTPS 아님).
- 화면에는 예약자 본인 것 외에 다른 사람의 번호가 나오지 않는다. 명단 전체는 비밀번호 뒤에만 있다.

## 6. API (고칠 때 참고)

전부 `server/booth.js` 한 파일에 있다. 결제 코드와 겹치는 부분은 없다.

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/api/booth/queue?id=` | 활동별 대기 팀 수, `id` 를 주면 그 예약의 현재 순서 |
| POST | `/api/booth/reservations` | 예약 접수 → 접수 안내 발송 |
| POST | `/api/booth/admin/list` | 명단 (비밀번호 필요) |
| POST | `/api/booth/admin/complete` | 체험 완료 → 줄 당김 → 호출 발송 |
| POST | `/api/booth/admin/cancel` | 취소 (완료와 동일하게 줄 당김) |
| POST | `/api/booth/admin/close` | 오늘 그 체험존 마감 (완료 100팀 이상일 때만) |
| POST | `/api/booth/admin/reopen` | 마감 해제 |
| POST | `/api/booth/admin/test` | 발송 테스트 |

- **호출 대상이 되는 조건**: 오늘 줄에서 앞이 5팀 이하 · 아직 안 불림 · 접수 문자를 보낸 지 6초가 지남 · 실패했다면 8초가 지났고 3번 미만. 예약·완료·취소 때마다, 그리고 10초마다 이 조건으로 훑는다.
- 한 번에 여러 사람을 부를 때는 **보내기 전에** 전원에게 호출 표시를 찍는다. 체험 완료를 연달아 누르면 발송을 기다리는 사이에 같은 함수가 또 돌 수 있는데, 전에는 이때 같은 사람에게 호출이 두 번 갈 수 있었다.
- 호출 기준은 `server/booth.js` 의 `CALL_AHEAD = 5`. 여기만 고치면 "몇 팀 남았을 때 부를지"가 바뀐다.
- 한 번 부른 사람은 다시 부르지 않는다(`calledAt`). 완료를 몰아서 눌러 순서를 건너뛰어도 빠지지 않도록, 정확히 5가 아니라 **5 이하**를 본다.
- 접수할 때 이미 앞이 5팀 이하면 접수 문자를 보낸 **직후에 호출 문자를 따로 한 통 더** 보낸다. 전에는 한 통으로 합쳤는데, 줄이 비었을 때 두 안내가 한 문장에 뒤엉켜 무슨 말인지 알 수 없었다.
- 같은 번호로 같은 활동을 두 번 예약하면 새로 잡지 않고 원래 순서를 돌려준다.
