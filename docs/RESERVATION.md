# 체험 예약 — 운영 안내

부스 앞에 줄을 세우지 않고, 방문자가 자기 휴대폰으로 예약하고 순서를 확인하게 하는 기능이다.
활동 넷(감각등록·감각추구·감각예민·감각회피)이 **각자 따로 줄을 선다.**

---

## 1. 지금 되는 것 / 아직 안 되는 것

| | 상태 |
|---|---|
| 이름·전화번호·학과로 예약 | **된다** |
| 현재 대기 팀 수 보기 | **된다** (바뀌는 즉시 — 3-2절) |
| 내 앞에 몇 팀 남았는지 보기 | **된다** |
| 운영자 화면에서 명단 보기 · 체험 완료 · 취소 | **된다** |
| 운영자 **마감 · 마감해제(줄 초기화)** · 자정 초기화 | **된다** (2026-09-18) — 3-1절 |
| 예약 접수 / 5팀 남았을 때 **문자 발송** | **된다** (2026-09-08 Solapi 연결) — 남은 것은 충전뿐, 4절 |

발송이 끊겨 있어도 예약은 정상으로 접수되고, 방문자 화면에는 자기 순서가 실시간으로 보인다.
운영 화면 맨 위 줄에 지금 발송이 붙어 있는지가 표시된다.

> **행사 전에 충전할 것.** 2026-09-08 기준 잔액 0원 / 포인트 300p 다. 문자 한 통 20원대,
> 한 팀에 두 통(접수·호출)이 나가므로 **팀당 약 40원** — 300p 로는 일고여덟 팀이면 동난다.
> 100팀을 받을 생각이면 5,000원쯤 충전해 두면 넉넉하다. (호출은 앞이 5팀 이하가 될 때만 나가므로,
> 줄이 길면 한동안 접수 한 통씩만 나간다.)

## 2. 행사 당일

```bash
npm run dev
```

방문자 휴대폰이 붙어야 하므로 **같은 와이파이**에서 노트북의 주소를 열어야 한다.

```bash
API_HOST=0.0.0.0 npm run dev -- --host
```

- 터미널에 뜨는 `Network: http://192.168.x.x:5173` 이 방문자가 열 주소다. QR 코드로 만들어 부스에 붙이면 된다.
- `API_HOST=0.0.0.0` 은 같은 와이파이의 아무나 접속할 수 있게 여는 설정이다. **행사 중에만 쓰고 끝나면 되돌릴 것.**
- 예약 기록은 `server/data/booth.json` 파일 하나에 쌓인다. 노트북을 껐다 켜도 남아 있다.

## 3. 운영 화면

1. 화면 맨 아래 **푸터의 프리지아 로고를 2.5초 안에 다섯 번** 누른다.
2. 비밀번호 **3618** 을 넣는다.
3. 활동별 대기 팀 수와 예약자 명단이 뜬다.
   (비밀번호 창에서 **[마감]** 을 눌렀다면 명단 대신 체험존별 마감 버튼 넷이 뜬다 — 3-1절)

- **이름으로 찾기** — 맨 위 검색칸에 이름(또는 번호 뒷자리)을 넣으면 그 사람이 잡아 둔 예약이 **날짜와 함께** 활동별로 한 번에 뜬다(지난날 기록까지). 한 사람이 네 활동에 다 줄을 설 수 있어서, "제가 예약했는데요" 하고 오는 사람을 가릴 때 쓴다. 상태는 `진행 중`(그 줄 맨 앞), `호출함 · 앞 N팀`, `대기 · 앞 N팀`, `완료`/`사용자 취소`/`관리자 취소`, `만료`(어제 대기로 남은 것), `초기화`(마감해제로 줄에서 빠진 것) 중 하나다. 동명이인은 번호로 구분한다.
- **호출 상태가 줄마다 보인다** — `호출함`(실제로 나감), `호출할 차례(문자 미연결)`, **`호출 문자 실패 — 직접 불러 주세요`**. 실패가 뜨면 그 팀은 직접 부르면 된다.
- **체험 완료** — 그 팀을 줄에서 뺀다. 뒤에 선 팀이 한 칸씩 당겨지고, 그 순간 앞이 5팀 이하가 된 사람에게 "부스로 오세요" 안내가 나간다.
- **취소** — 안 온 팀을 뺀다. 완료와 똑같이 줄이 당겨진다. 노쇼 하나가 줄을 막지 않도록 반드시 쓸 것. 끝난 팀 목록에 **관리자 취소**로 남는다.
- **사용자 취소**(2026-09-21) — 방문자가 예약한 화면의 **[예약 취소]** 로 스스로 빠질 수 있다. 이 화면에서 그 줄이 곧바로(알림으로, 1초 안쪽) 사라지고
  끝난 팀 목록에 **사용자 취소**로 남는다. 접힌 "끝난 팀" 줄에도 `· 사용자 취소 N` 으로 수가 보인다. 끝난 팀은 방금 끝난 것부터 보인다.
  취소에는 **예약한 그 휴대폰에만 한 번 건넨 취소 열쇠**가 필요하다. 남의 번호를 알아도(같은 번호로 다시 예약하면 "이미 예약하셨습니다"로 순서는 보인다)
  그 기기에는 취소 버튼이 나오지 않고, 서버도 열쇠 없는 취소를 거절한다. 그 응답에는 이름·번호도 싣지 않는다. 체험을 마쳤거나 이미 취소된 예약은 취소되지 않는다.
  예약한 휴대폰이 아닌 곳(휴대폰을 바꿨거나 저장소를 지운 경우)에서 취소하려면 부스에서 관리자 취소로 처리한다.
- 비밀번호는 **서버가 확인한다.** 화면 코드에는 정답이 없어서 개발자 도구로 뜯어봐도 명단이 나오지 않는다.
- 탭을 닫으면 로그인이 풀린다(sessionStorage). 부스 휴대폰을 잠깐 두고 가도 다음 사람이 명단을 열지 못한다.
- 비밀번호를 바꾸려면 `.env` 에 `BOOTH_ADMIN_PASSWORD=원하는번호`.

## 3-1. 마감 · 마감해제(줄 초기화) · 자정 초기화 (2026-09-18)

**정원은 없다.** 몇 팀이 서든 저절로 닫히지 않는다. 더 받지 않을 때는 운영자가 **마감**을 누른다.
네 체험존이 각자 따로다.

| 상황 | 방문자 화면 | 서버 |
|---|---|---|
| 평소 | 예약 폼 | 접수 (번호 제한 없음) |
| 운영자가 **마감**을 눌렀다 | **오늘은 마감되었어요. 내일 다시 만나요.** | 새 예약 거절 |
| 운영자가 **마감해제**를 눌렀다 | 예약 폼 | 대기 0팀, **다음 예약이 1번** |
| 한국 시각 00시가 지났다 | 예약 폼 | 마감 풀림, 대기번호 1번부터 다시 |

### 마감 · 마감해제 누르는 곳 (둘 다 같은 동작)

1. **푸터 로고를 다섯 번** → 비밀번호 창의 **[마감]** → 비밀번호 **3618** → 확인.
   (비밀번호를 먼저 넣고 [마감]을 눌러도 된다. [확인]만 누르면 예전처럼 예약자 목록으로 간다.)
   감각등록 · 감각추구 · 감각예민 · 감각회피 버튼 넷이 뜬다.
2. 또는 예약자 목록(운영 화면)의 체험존마다 있는 마감 줄.

- 누를 때마다 한 번 더 묻는다. 그 체험존만 바뀌고 다른 체험존은 그대로다.
- **마감** — 새 예약만 막는다. **이미 줄에 선 팀은 그대로** 자기 순서를 보고, 호출 문자도 받고, 체험 완료도 계속 누를 수 있다.
  마감한 체험존의 버튼은 **마감해제**로 바뀐다.
- **마감해제** — 그 체험존의 **줄을 처음부터 다시 시작한다.** 대기 0팀, 다음 예약이 1번.
  - 해제하는 순간 **아직 대기 중인 팀이 있으면 줄에서 빠진다**(호출 문자도 가지 않는다). 누르기 전 확인 창에
    "지금 대기 중인 N팀은 줄에서 빠집니다"라고 뜬다. 보통은 줄을 다 모신 뒤에 누르면 된다.
  - 빠진 사람의 휴대폰 화면에는 "대기 줄이 새로 시작되었어요. 다시 예약해 주세요."와 폼이 뜬다. 같은 번호로 다시 예약할 수 있다.
  - **기록은 지우지 않는다.** 이름 검색에서 `초기화`로 찾힌다. 운영 화면의 체험존별 목록과 완료 수는 새 줄 기준이다.
  - 해제 버튼이 두 번 눌리거나 오래된 화면에서 늦게 눌려도 **초기화는 한 번뿐**이다 — 마감 상태일 때만 초기화한다.
- 마감·초기화는 서버를 껐다 켜도 유지되고, 00시가 지나면 마감은 저절로 풀린다.
- 번호는 한 줄 안에서 다시 쓰지 않는다. 취소가 있어도 다음 번호는 계속 올라간다.

### 자정 초기화

**00시에 무엇을 "지우는" 작업은 없다.** 모든 조회가 "오늘" 기록만 보도록 되어 있어서 날짜가 바뀌면 저절로 새 줄이 된다.
마감해제도 같은 방식이다 — 해제할 때마다 그날 그 체험존의 "줄 순번"이 하나 오르고, 모든 조회가 지금 순번의 기록만 본다.

- 한국 시각 기준이다. **서버가 UTC 로 돌아도**(Railway 가 그렇다) 한국 00시에 바뀐다. 서버 날짜를 그대로 썼다면
  한국 오전 9시에 줄이 통째로 초기화됐을 것이다.
- 타이머에 기대지 않으므로 **00시에 서버가 꺼져 있었어도** 켜지는 순간 새 날로 맞게 돈다.
- 어제 대기로 남아 있던 예약은 **만료**가 된다. 오늘 줄에 섞이지 않고, 그 사람 화면에서도 순서가 사라져 폼으로 돌아간다
  ("지금 입장해주세요"가 잘못 뜨지 않는다). 운영 화면에서 완료·취소할 수도 없다.
- **지난날 기록은 지워지지 않는다.** 줄과 버튼은 오늘 것만 보이지만, 이름 검색은 지난날까지 찾고 날짜를 함께 보여 준다.

### 검증한 것

**다시 돌리려면 `npm run test:booth`** (약 6분). 진짜 문자는 한 통도 나가지 않는다 — 키를 비우거나,
지연·실패를 흉내 내는 가짜 Solapi 서버(`SOLAPI_BASE_URL`)로 돌린다. 예약 파일도 임시 폴더를 쓴다.

실제 서버를 여러 대 띄워 규칙 176가지(`tests/booth-rules.test.mjs`, 사용자 취소·남의 번호로 취소 시도 포함), 문자 경로 37가지(`tests/booth-sms.test.mjs`), 장면별 문자 41가지(`tests/booth-scenarios.test.mjs`, 4절), 바로 반영 46가지(`tests/booth-live.test.mjs`, 3-2절)를 확인했다(자정은 서버 시계를 23:59:40 으로
밀어 두고 **실제로 넘어가게** 해서).

- 150팀 예약 전부 성공, 번호 1..150 빠짐없음, 100에서 막히지 않음, 정원 값이 응답에 없음
- 취소해도 번호 재사용 안 함
- 완료 0 에서도 마감 성공, 두 번 눌러도 이상 없음, 마감 후 예약 거절·문구 정확, 다른 체험존 영향 없음
- 마감 중에도 줄에 선 사람은 자기 순서를 받고, 체험 완료가 되고, 앞 5팀이 된 팀에게 호출이 감
- 마감해제: 대기 147팀 빠짐 → 대기 0 → 다음 예약 1번(앞 0팀), 빠진 사람은 `reset`·완료/취소 불가·같은 번호로 재예약 가능,
  기록 보존, 파일에도 기록, **해제 두 번 눌러도 새 줄은 안 지워짐**, 마감 안 된 체험존 해제는 아무것도 안 함,
  10초 정기 점검 뒤에도 빠진 팀에게 호출 없음, 새 줄 1번은 접수 + 호출
- 마감 → 해제 두 번째도 다시 1번부터, 비밀번호 틀리면 마감·해제 불가
- 자정 통과: 날짜 +1, 마감 풀림, 줄 순번도 0 으로, 대기 0, 번호 1부터, 어제 대기는 만료·완료 불가, 어제 기록(초기화 포함) 보존
- 서버 시간대를 UTC·로스앤젤레스로 바꿔도 한국 날짜, 연말·윤년 경계
- 재시작 후 마감·줄 순번·`reset` 기록·번호 유지, 재시작 뒤 해제도 정상, 깨진 예약 파일은 덮어쓰지 않고 옆에 백업
- 같은 IP 에서 50건 동시 예약 성공·번호 중복 없음
- 화면(휴대폰 크기): 푸터 [마감] → 3618 → 버튼 넷, 마감 → 버튼이 마감해제로, 새 방문자에게 마감 문구·이미 선 사람은 자기 순서,
  해제 → 대기 0 · 빠진 사람에게 "대기 줄이 새로 시작되었어요" · 다시 예약하면 1번, 틀린 비밀번호는 거절

## 3-2. 바로 반영 — 새로고침 없이 (2026-09-19)

**증상**: "마감이나 마감해제를 눌렀을 때 한 번에 작동 안 함. 새로고침을 해야 작동함."
서버는 누르는 즉시 바뀌어 있었다(캐시도 아니었다). 문제는 전부 화면 쪽이었다.

| 원인 | 어떻게 보였나 | 지금 |
|---|---|---|
| **배포 전에 열어 둔 탭**이 옛 화면 코드를 계속 돌림 (휴대폰 사파리는 탭을 며칠씩 살려 둔다) | 옛 운영 화면의 마감 버튼이 새 서버 앞에서 계속 막힘 → 새로고침해야 됨 | 응답마다 배포된 빌드 이름이 붙고, 다르면 화면이 **안전한 때에 한 번** 스스로 새로 불러온다 |
| 방문자 화면이 **15초마다** 묻기만 함. 휴대폰은 탭을 옮기거나 화면을 켤 때 그 주기를 더 늦춤 | 다른 휴대폰에서 마감해도 최대 15초 넘게 그대로 | 서버가 바뀌는 즉시 **알림**(SSE)을 보낸다. 실측 **0.14~0.35초** 안에 바뀐다. 화면이 다시 보이는 순간에도 곧바로 다시 묻는다 |
| 운영 화면에서, 누르기 전에 출발한 목록 응답이 늦게 도착해 버튼을 **옛 모양으로 되돌림** | 한 번 눌러서는 안 된 것처럼 보임 | 누른 뒤 서버의 답으로 곧바로 바꾸고, 그보다 먼저 출발한 응답은 버린다. 버튼이 바뀌는 데 **약 0.01초** |
| 느린 와이파이에서 방문자 화면이 "더 새 요청이 출발했으면 버린다" 규칙 때문에 **어떤 응답도 반영 못 함** | 계속 옛 상태 | "이미 반영한 것보다 나중에 출발한 응답만 받는다"로 바꿈 |

**배포 후 한 번은 직접 새로고침**: 이번 배포 **전에** 열려 있던 탭(운영자 휴대폰·부스 태블릿)은 이 장치가 없는 옛 코드라
스스로 새로 불러오지 못한다. 한 번씩 새로고침해 두면 그 뒤로는 알아서 따라간다. 옛 화면에서 마감·해제를 누르면
서버가 **"화면이 예전 것입니다. 새로고침한 뒤 다시 눌러 주세요."** 로 거절한다(옛 화면의 해제는 되묻지 않고 줄을 비우기 때문).

지키는 것:
- 알림에는 번호 하나뿐이다 — 이름·전화번호는 절대 싣지 않는다. 받은 화면이 자기 것을 다시 묻는다.
- 화면이 가려져 있으면 연결을 끊고 묻지도 않는다(배터리). 다시 보이면 곧바로 묻고 다시 잇는다.
- 알림이 막혀도 틀린 상태로 남지 않는다 — 5초(알림이 살아 있으면 15~20초)마다 따로 묻는다.
- 스스로 새로 불러오기는 **한 번만**, 그리고 비밀번호 창·마감 버튼 판이 열려 있거나 무언가를 치고 있거나 예약 칸에
  적어 둔 것이 있거나 방금 누른 요청이 오가는 중이면 **기다린다.** 여러 화면이 같은 순간에 몰리지 않게 몇 초씩 흩는다.
- "안내 문자를 보내지 못했습니다"와 "대기 줄이 새로 시작되었어요" 안내는 화면이 새로 불러와져도 남는다.
- 해제는 **"대기 N팀이 빠집니다" 확인을 받은 요청만** 줄을 비운다(확인 창을 띄우는 지금 화면만 그 표시를 싣는다).
- 운영 목록은 알림마다 받지 않고 2.5초씩 묶는다(한 번에 명단 전체를 받기 때문). 마감 버튼 판은 체험존 상태만 받는다.
- 대기 현황 응답은 어디에도 캐시되지 않는다(`Cache-Control: no-store`). 연결 유지 65초(프록시보다 길게).

검증: `tests/booth-live.test.mjs` 44가지(`npm run test:booth` 에 포함) — 마감·해제·예약·완료·취소·**한국 00시**마다 알림이
0.1~0.2초 안에 도착, 20건 몰려도 알림은 한 번으로 묶임, 바뀐 것이 없거나 거절된 요청은 알리지 않음, 연결 유지 신호,
빌드 이름·no-store 헤더, 옛 화면 마감·해제 거절, 확인 없는 해제 거절, HEAD 요청이 연결을 붙잡지 않음.
화면은 휴대폰 크기로 직접: 다른 기기에서 마감/해제 → 방문자 화면이 새로고침 없이 0.14~0.35초 안에 바뀜,
가려진 동안 바뀐 것은 다시 보이는 순간 바로 반영, 옛 빌드로 열려 있던 탭이 새 서버를 만나자 한 번 스스로 새로 불러옴,
마감 버튼 판·운영 화면 버튼이 누르자마자 바뀜(목록 응답을 1.5초 늦춰도 완료한 줄은 0.01초 만에 빠짐),
다른 기기가 바꾸면 판과 목록도 따라가고 맞지 않게 된 안내 문구는 감춰짐.

## 4. 발송 — 지금 상태와 문구

**2026-09-08 에 Solapi 계정을 붙였다. 지금은 문자(SMS)로 나간다.**

- 발신번호 등록 완료(ACTIVE, 2028-09-08 까지). 번호와 키는 `.env` 의 `SMS_SENDER`·`SOLAPI_*` 에 있고 git 에 올라가지 않는다 — 저장소가 공개돼도 개인 번호가 새지 않게 문서에도 적지 않는다.
- 키가 채팅으로 오간 값이라, 행사가 끝나면 Solapi 콘솔에서 **키를 새로 발급(폐기)** 해 두는 편이 안전하다.
- 확인은 운영 화면 위쪽 **테스트 발송** 으로. 자기 번호에 한 통 보내 보고 들어갈 것.
- **발송이 실패하면 운영 화면 맨 위에 이유가 그대로 뜬다**(2026-09-09). `HTTP 401 · 생성한 signature를 확인하세요` 면 키가 틀렸거나 앞뒤에 공백이 붙은 것이다. 같은 줄에 키·시크릿의 **글자 수**도 나온다 — Solapi 키는 16자, 시크릿은 32자다. 숫자가 다르면 붙여넣기가 잘못된 것이다.

- **지문으로 대조한다.** 화면에 키·시크릿의 글자 수와 함께 앞 여섯 자리 해시가 뜬다. 값 자체는 나오지 않으므로 안전하고, 올바른 값인지 눈으로 확인할 수 있다. 길이만 보면 "32자인데 다른 값"을 놓친다.

### 장면별로 실제로 나가는 문자 (2026-09-21 확인)

`tests/booth-scenarios.test.mjs` 가 가짜 Solapi 서버를 붙여 서버가 Solapi 에 **보내는 요청을 그대로 받아 적는다**(진짜 문자는 나가지 않는다).
휴대폰에 찍히는 글자와 같다 — 통신사가 앞에 붙이는 `[Web발신]` 만 빼고. 모두 SMS, 90바이트 이하.

| 장면 | 그 사람이 받는 문자 |
|---|---|
| 앞에 5팀 **초과**(예: 7팀)로 예약 | 접수 한 통만: `[작업치료학과 프리지아] 홍길동님, 8번으로 접수되었습니다. 5팀 남으면 연락드립니다.` |
| 앞에 **정확히 5팀**으로 예약 | 접수, 6초 뒤 호출: `홍길동님, 5팀 남았습니다. 부스 앞에서 대기해주세요.` |
| 앞 6팀 → 한 팀 **체험 완료** → 5팀 | 그 순간 호출 한 통: `홍길동님, 5팀 남았습니다. 부스 앞에서 대기해주세요.` (다른 사람에게는 새 문자 없음) |
| 앞 6팀 → 한 팀 **취소**(관리자든 본인이든) → 5팀 → 한 팀 **체험 완료** → 4팀 | 5팀이 되는 순간 호출 한 통(`5팀 남았습니다`). 4팀이 될 때는 **아무것도 안 감** — 호출은 한 사람에게 한 번 |
| 앞 6팀 → 체험 완료 → 5팀 → 본인 취소 → 4팀 | 위와 같다(5팀 순간 한 통, 4팀엔 없음) |
| 취소와 완료가 거의 같은 순간(0.05초 차) | 호출 한 통. 남은 팀 수는 보낸 순간의 값(실측 `5팀`) |
| 줄이 비어 있을 때 예약(앞 0팀) | 접수, 6초 뒤 `홍길동님, 지금 입장해주세요. 부스 앞으로 와주세요.` |

취소 자체(관리자·본인)는 누구에게도 문자를 보내지 않는다. 줄이 당겨져 앞이 5팀 이하가 된 사람이 처음 생길 때만 그 사람에게 호출이 간다.

### 나가는 문구

**접수와 호출은 언제나 따로 간다.** 한 통으로 붙이면 "접수됐습니다"인지 "지금 오세요"인지 읽는 사람이 구분하지 못한다.
줄이 비어 있을 때 예약하면 접수 한 통이 가고 곧바로 호출 한 통이 따로 간다. 한 사람이 받는 문자는 언제나 두 통이다.

```
접수         [작업치료학과 프리지아] 홍길동님, 12번으로 접수되었습니다. 5팀 남으면 연락드립니다.   83바이트 · SMS
호출         홍길동님, 5팀 남았습니다. 부스 앞에서 대기해주세요.                            55바이트 · SMS
호출(차례)    홍길동님, 지금 입장해주세요. 부스 앞으로 와주세요.                             54바이트 · SMS
```

### 90바이트를 넘기지 말 것 — 요금 문제가 아니다

넘는 순간 SMS 가 LMS 가 되는데, LMS 에는 **제목(subject)** 이 붙는다. 휴대폰은 그 제목을 본문 위,
`[Web발신]` 보다 **앞줄에 굵게** 띄운다. 그리고 LMS 와 SMS 는 통신사에서 다른 경로로 나가
**짧은 SMS 가 긴 LMS 를 추월한다** — 접수(LMS)와 호출(SMS)을 함께 보냈더니 "지금 입장해주세요"가
먼저 도착한 사고가 실제로 있었다. 둘 다 SMS 면 경로가 같아 순서가 지켜지고, 제목 줄도 없고,
값도 통당 20원대다(**팀당 약 40원**).

세는 법은 한글 2, 영문·숫자 1. 이름이 유난히 길어 넘칠 것 같으면 `bookedText` 가 `작업치료학과` 를
스스로 떼어 90 안에 맞춘다.

### 그 밖에

- `[Web발신]` 자체는 **뗄 수 없다.** 웹·API 로 나가는 문자에 통신사가 붙이는 표시다.
  없애려면 알림톡이나 기업메시징(등록된 사업자용) 서비스로 가야 한다.
- `5팀 남으면` 의 숫자는 `CALL_AHEAD` 를 그대로 끼워 넣는다. 기준을 바꾸면 문구도 같이 바뀐다.
- **접수 문자와 호출 문자는 `CALL_DELAY_MS`(6초) 를 두고 나간다.** 줄이 짧을 때 예약하면 두 통이
  연달아 나가는데, 같은 초에 통신사로 들어가면 도착 순서가 보장되지 않는다. 예약 응답은 지연 없이
  먼저 돌아가므로 화면에서 자기 순서는 곧바로 보인다.
- **호출 문자에는 활동 이름이 들어가지 않는다**(사용자가 정한 문구). 한 사람이 여러 활동에 줄을 서 있으면
  어느 부스인지 문자만으로는 알 수 없다 — 넣으려면 `callUpText` 에 `ACTIVITIES[r.activity].title` 을 붙이면 된다.

### 카카오톡(알림톡)으로 바꾸고 싶다면

**웹페이지가 혼자서 카카오톡을 보낼 방법은 없다.** 모르는 번호로 카카오톡을 보내는 것은 *알림톡*이고,
알림톡을 쓰려면 다음이 전부 있어야 한다.

1. **카카오톡 채널** 개설 + 비즈니스 채널 전환
2. **발송 대행사** 계정 — Solapi(구 쿨SMS)·알리고·NHN Cloud 등. 이 코드는 **Solapi** 기준으로 붙여 두었다.
3. **템플릿 사전 심사** — 문구를 미리 등록해 승인받아야 한다(영업일 1~3일). 승인된 문구만 나간다.
4. **발신번호 사전 등록** — 학생회 대표번호 등

알림톡이 부담스러우면 **문자(SMS/LMS)만 써도 된다.** 채널도 템플릿 심사도 필요 없고,
대행사 계정과 발신번호 등록만 있으면 된다. 아래에서 `KAKAO_*` 를 비워 두면 자동으로 문자로 나간다.

`.env` 에 아래 셋은 이미 들어가 있다. 알림톡을 쓰려면 `KAKAO_*` 를 더 넣으면 되고,
비워 두면 지금처럼 문자로 나간다.

```
SOLAPI_API_KEY=...              # 넣어 둠
SOLAPI_API_SECRET=...           # 넣어 둠
SMS_SENDER=...                  # 넣어 둠 (등록 완료)

# 알림톡까지 쓸 때만
KAKAO_PFID=...                  # 카카오 채널 발신 프로필 id
KAKAO_TEMPLATE_BOOKED=...       # 접수 안내 템플릿 id
KAKAO_TEMPLATE_CALLUP=...       # 호출 템플릿 id
```

템플릿을 등록할 때 쓸 문구(치환 변수는 `#{name}` `#{title}` `#{teamNo}` `#{ahead}`):

- 접수 — `[프리지아] #{name}님 #{teamNo}번 접수. 앞에 #{ahead}팀. 순서 되면 다시 알려드릴게요.`
- 호출 — `[프리지아] #{name}님 앞에 #{ahead}팀! #{title} 부스로 와주세요.`

알림톡은 통당 8~10원대라 문자보다 싸지만, 채널·심사가 붙는다. 하루짜리 부스면 문자로 충분하다.

**발송에 실패해도 예약은 절대 실패하지 않는다** — 줄에 선 사람이 사라지면 안 되기 때문이다.
실패 기록은 각 예약에 남고, 운영 화면에서 순서를 보고 직접 부를 수 있다.

## 5. 개인정보

이름·전화번호·학과가 `server/data/booth.json` 에 평문으로 쌓인다.

- **행사가 끝나면 이 파일을 지울 것.** 지우면 그날의 명단이 전부 사라진다.
- 서버를 학교 밖 인터넷에 열어 두지 말 것. 같은 와이파이 안에서만 쓰는 것을 전제로 만들었다(HTTPS 아님).
- 화면에는 예약자 본인 것 외에 다른 사람의 번호가 나오지 않는다. 명단 전체는 비밀번호 뒤에만 있다.

## 6. API (고칠 때 참고)

전부 `server/booth.js` 한 파일에 있다. 결제 코드와 겹치는 부분은 없다.

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/api/booth/queue?id=` | 활동별 대기 팀 수, `id` 를 주면 그 예약의 현재 순서 |
| GET | `/api/booth/events` | 바뀜 알림(SSE). `hello`(빌드 이름) 뒤로 `data: {"v":번호}` 만 흐른다 |
| POST | `/api/booth/reservations` | 예약 접수 → 접수 안내 발송 |
| POST | `/api/booth/reservations/cancel` | 본인 취소 `{id, key}`(key 는 예약 응답의 `cancelKey`, 그 기기에만) — 오늘 대기 중일 때만. 줄 당김 → 필요하면 호출 발송. 운영 화면엔 "사용자 취소" |
| POST | `/api/booth/admin/list` | 명단 (비밀번호 필요) |
| POST | `/api/booth/admin/zones` | 체험존 넷의 상태만 (마감 버튼 판용, 명단 없음) |
| POST | `/api/booth/admin/complete` | 체험 완료 → 줄 당김 → 호출 발송 |
| POST | `/api/booth/admin/cancel` | 관리자 취소 (완료와 동일하게 줄 당김). 운영 화면엔 "관리자 취소" |
| POST | `/api/booth/admin/close` | 그 체험존 마감 — 새 예약만 막는다. `X-Client-Build` 헤더 없는(옛) 화면은 409 RELOAD |
| POST | `/api/booth/admin/reopen` | 마감 해제 — 그 체험존 줄을 처음부터(대기 0, 다음 1번). 마감 상태일 때만. 대기 팀이 있으면 `reset: true` 필요(없으면 409 CONFIRM_RESET), 옛 화면은 409 RELOAD |
| POST | `/api/booth/admin/test` | 발송 테스트 |

- **호출 대상이 되는 조건**: 오늘 줄에서 앞이 5팀 이하 · 아직 안 불림 · 접수 문자를 보낸 지 6초가 지남 · 실패했다면 8초가 지났고 3번 미만. 예약·완료·취소 때마다, 그리고 10초마다 이 조건으로 훑는다.
- 한 번에 여러 사람을 부를 때는 **보내기 전에** 전원에게 호출 표시를 찍는다. 체험 완료를 연달아 누르면 발송을 기다리는 사이에 같은 함수가 또 돌 수 있는데, 전에는 이때 같은 사람에게 호출이 두 번 갈 수 있었다.
- 호출 기준은 `server/booth.js` 의 `CALL_AHEAD = 5`. 여기만 고치면 "몇 팀 남았을 때 부를지"가 바뀐다.
- 한 번 부른 사람은 다시 부르지 않는다(`calledAt`). 완료를 몰아서 눌러 순서를 건너뛰어도 빠지지 않도록, 정확히 5가 아니라 **5 이하**를 본다.
- 접수할 때 이미 앞이 5팀 이하면 접수 문자를 보낸 **직후에 호출 문자를 따로 한 통 더** 보낸다. 전에는 한 통으로 합쳤는데, 줄이 비었을 때 두 안내가 한 문장에 뒤엉켜 무슨 말인지 알 수 없었다.
- 같은 번호로 같은 활동을 두 번 예약하면 새로 잡지 않고 원래 순서를 돌려준다.
